# Прокат горнолыжного снаряжения. Фронтенд.

React + TypeScript + Vite. Клиентские страницы и рабочее место администратора в одном приложении.

## Работа с существующим API

```powershell
npm run dev
```

Бэкенд должен быть отдельно запущен его владельцем на `http://127.0.0.1:8000`. Фронтенд обращается к `/api/*`; Vite перенаправляет запросы к бэку, удаляя `/api`. Например, `/api/bookings` → `http://127.0.0.1:8000/bookings`. Настройки CORS бэка менять не требуется.

Если адрес другой, скопировать **внутри frontend** `.env.example` в `.env.local` и задать:

```dotenv
API_TARGET=http://127.0.0.1:8000
VITE_API_BASE=/api
VITE_RENTAL_TIMEZONE=Europe/Moscow
```

`VITE_RENTAL_TIMEZONE` должен совпадать с часовым поясом компьютера, на котором запущен бэк: его проверки используют `datetime.now()`. Фронтенд не получает часовой пояс через API. После изменения `.env.local` перезапустить Vite.

## Что реализовано

| Раздел                            | Возможности                                                                                        |
| --------------------------------- | -------------------------------------------------------------------------------------------------- |
| Главная `/`                       | Категории из API, локальные SVG-иллюстрации, описание процесса бронирования                        |
| Бронирование `/booking/:category` | Размеры, 7 дней, часовые интервалы, ФИО и телефон, сводка, подтверждение с номером                 |
| Мои брони `/my-bookings`          | Поиск по полному телефону, состав брони, статусы, отмена с подтверждением                          |
| Вход `/admin/login`               | Авторизация, проверка сессии, обработка неверного пароля и истёкшего токена                        |
| Брони `/admin`                    | Поиск по телефону или ID, подтверждение выдачи и возврата                                          |
| Инвентарь `/admin/inventory`      | Фильтры типа/состояния, поиск кода/названия/размера, добавление, поломка, восстановление, удаление |

## Как фронт учитывает бэк

- Создание брони отправляет только поля `BookingCreate`. Коньки: `size_value`; лыжи/сноуборд: `size_bucket` и `boot_size_value`. Одежда и защита доступны в учёте инвентаря, но не добавляются в бронь, поскольку API создания этого не поддерживает.
- Размеры S/M/L/XL читаются из справочника. Публичного списка доступных EU-размеров нет: предложены 36–46 и ввод другого размера 20–55; наличие проверяется через `/availability`.
- Выбираются отдельные часовые интервалы 10:00–20:00, в том числе несмежные. Сводка объединяет только смежные часы. Текущий и прошедшие часы отключены, как в проверке создания брони на бэке.
- Доступность обновляется каждые 30 секунд и при возвращении на вкладку. Свободные часы по отдельности не гарантируют один комплект на все часы: окончательное решение принимает `/bookings`. При 409 возвращаем к выбору времени, сохраняя ФИО и телефон.
- Телефон очищается от форматирования; начальная `8` заменяется на `7` только у 11-значного номера, как на бэке. Фамилия, имя, отчество передаются отдельно.
- Лимит 4 активных броней проверяется сервером
- Статусы брони: `active`, `issued`, `completed`, `cancelled`. Отмена доступна только для `active`; выдача — `active`; возврат — `issued`.
- Админский список броней требует полный телефон; поиск ID использует отдельный endpoint. Поиск по последним четырём цифрам из раннего описания проекта не предлагается, поскольку текущий код его не поддерживает.
- Типы инвентаря собираются из справочников категорий с удалением повторов. Код новой единицы назначает бэк. Удаление связанного с бронями инвентаря может быть отклонено сервером — причина показывается в диалоге.
- Выданный инвентарь возвращается через завершение брони. Ручная отметка поломки и восстановление доступны для невыданных единиц. Отметка поломки не отменяет уже существующие брони — интерфейс сообщает об этом.
- Токен сотрудника хранится в `sessionStorage`; по 401 очищаются токен и кэш админки, открывается вход. У деморежима отдельный ключ токена.
- POST/PATCH/DELETE автоматически не повторяются. После неопределённого результата создания брони предлагается сначала проверить «Мои брони», чтобы избежать дубля.

## Сборка и проверки

```powershell
npm run build
npm test -- --workers=2
npm run test:demo
npm run preview
```

`build` выполняет строгую проверку TypeScript и создаёт `dist/`. `preview` позволяет просмотреть production-сборку и использует тот же API-прокси. Для постоянного размещения нужно настроить на веб-сервере прокси `/api` к FastAPI и SPA-fallback на `index.html`; прокси Vite не входит в статические файлы `dist/`.

Браузерные тесты используют установленный **Microsoft Edge** и самостоятельно поднимают Vite на 5173. Перед тестами остановить демосервер на этом порту. На системе без Edge установить браузер или сменить `channel` в `playwright.config.ts` на доступный.

`test:demo` отдельно проверяет полный демонстрационный сценарий без перехвата API: создание брони, обновление страницы, вход сотрудника, выдачу и возврат. Для этого временно используется порт 5174. На момент сдачи прошли 10 основных сценариев и 1 демонстрационный.

`npm run format` форматирует исходники через Prettier.

Тестируются оформление трех категорий и точные тела запросов, запрет прошедших часов, конфликт 409, поиск/отмена, авторизация, выдача/возврат, изменения инвентаря, истечение сессии, недоступность API и мобильный экран. Ответы API в тестах подставляются на уровне браузера по контрактам бэка. Это проверка фронтенда, не интеграционный тест реального FastAPI/PostgreSQL.

## Структура

```text
src/
  App.tsx                    маршруты, шапка и подвал
  main.tsx                   React, Router, QueryClient
  types.ts                   типы запросов и ответов API
  styles.css                 оформление и адаптивность
  components/
    EquipmentArt.tsx         SVG-иллюстрации снаряжения
    ui.tsx                   общие состояния, статусы и диалоги
  lib/
    api.ts                   HTTP-клиент, ошибки и авторизация
    demo.ts                  явно включаемый локальный деморежим
    format.ts                даты, часы, телефон, категории
  pages/
    Home.tsx                 главная
    Booking.tsx              шаги оформления
    MyBookings.tsx           поиск и отмена
    Admin.tsx                вход, брони, инвентарь
tests/app.spec.ts            браузерные сценарии
tests/demo.spec.ts           проверка самостоятельного деморежима
```
